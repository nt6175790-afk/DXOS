# Keycloak runtime hardening — 26/10/2026

The first hardening CI run found CA/JVM vulnerabilities in the previously pinned Keycloak 26.8.1 image: CVE-2026-114406, CVE-2026-91403 and CVE-2026-91415. Re-pulling the newer official 26.8.1 image removed the CA finding but retained the two JVM findings. Do not ignore these findings or disable scans.

Before implementation, the selected remediation is to keep the official, digest-pinned **Keycloak 26.8.1 distribution** and package it on a digest-pinned **Amazon Corretto OpenJDK 21.0.13** runtime with current security updates. This changes only the container's Java/OS packaging. No realm, user, password, client, issuer, PKCE requirement, DX-OS identity mapping or business role policy is changed. MySQL 8.0.44 and Prisma 6.19.3 remain unchanged.

Corretto is an OpenJDK distribution under GPL-2.0 with the Classpath Exception and bundled third-party notices, not a proprietary Oracle JDK. Runtime legal notices remain in the image; source and release details are available from https://github.com/corretto/corretto-21/releases/tag/21.0.13.0.10 . Keycloak remains Apache-2.0. DX-OS's own source remains Apache-2.0, with third-party licensing documented separately.

The reviewed Amazon Linux security repository snapshot is `2023.12.20261026`, confirmed from the repository's available `system-release` metadata. It updates the CA store, curl, brotli, libcap, pcre2 and Python packages inherited from the base image. A plain `dnf upgrade` would remain locked to the older repository and miss those patches. The installed OS release string may still show the older version after security-only updates, so it must not be used to infer the repository snapshot. The Dockerfile specifies the reviewed snapshot; future security updates require a new review/build/scan rather than silently changing the runtime.

The security Compose file and runtime scanner must reference the same built `dxos-security-keycloak` image. CI must run a disposable real-Keycloak test (discovery, public client S256, login, code exchange and signed ID token verification) and scan that built image, not the old upstream image. Test users, realm, passwords and tokens are ephemeral, in-memory test data; no test credentials are printed or committed. The container must be removed after testing. All HIGH/CRITICAL checks remain enabled and final status comes from the actual scan and CI, not the remediation plan.

The simple Docker demo on port 8090 keeps SSO disabled. This change affects the optional security stack on port 8088. Existing running containers are not replaced automatically by editing source; rebuild/recreate the optional Keycloak service deliberately using its existing local configuration. Existing named volumes must be retained.
