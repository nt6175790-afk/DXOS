# AI generation boundary

> DXOS-AI-003 implementation update ([spec](ai-agent-v1-spec.md), [HLD](ai-agent-v1-hld.md)): the endpoint now runs a read-only **agent** when the provider supports tool calling (`mock`, `ollama`, `vllm`). The model chooses among 12 read-only data tools plus `calculate`; every tool re-checks its own permission inside the organization, returns an allowlisted and size-bounded result, and reuses the owning module's read services (no text-to-SQL, no writes). The loop is bounded (3 tool rounds, 3 calls per round, per-call and total timeouts) and the answer carries `citations` and a numeric grounding check. `AI_PROVIDER` additionally accepts `ollama` and `vllm` with a server-configured `AI_BASE_URL`; `openai`/`gemini` keep the single-call legacy path. This supersedes the "no tools / agents / tool execution" and "mock returns fixed text" statements below; conversations are still client-supplied and not stored, there is still no RAG, embedding, vector store, streaming or autonomous mutation, and no migration was added.

POST /api/v1/organizations/:organizationId/ai/generate uses existing JWT, organization context, OrganizationPermissionGuard and ai:use. No default grants. Service rechecks authorization before admission and before returning output. Uploader/file/notification APIs are not involved; no tools or resource retrieval are available.

AiProvider accepts bounded normalized messages/model/output settings and request correlation plus AbortSignal. Business code does not use a vendor SDK. MockAiProvider is deterministic, credential-free, offline and clearly labeled mock; it returns fixed text, not echoed input. Its usage is a synthetic character/4 estimate, not billable vendor tokens. Only mock-v1 is supported. AI_PROVIDER accepts mock or disabled (production default disabled; development/test default mock). AI_MODEL is allowlisted, AI_TIMEOUT_MS integer 1–30000, default 5000. Unsupported configuration fails startup without echoing values. External adapters require separate review and must honor cancellation and return the normalized contract.

Limits: 16 user/assistant messages, 4000 characters each, 16000 total characters and 64000 UTF-8 bytes, non-whitespace content, maxOutputTokens 1–2048 default 256, temperature 0–2 default 0. Metadata is optional closed {purpose: general}, <=256 UTF-8 bytes, never stored/logged. No arbitrary provider/model options, actor/tenant fields, system role or query fields. Provider output is runtime checked: closed shape, text <=8192 characters, safe nonnegative usage counts (input <=1000000; output <=requested cap), bounded finish reason. Provider/model metadata is server-selected. Generated text is untrusted data and never executed.

AiRequest stores tenant/member FK, actor, server-selected provider/model, STARTED/SUCCEEDED/FAILED, request ID, nullable usage/timing/error category, created/completed timestamps. No prompt, response, metadata, secret or provider error columns. Additive migration 20260908000000_ai_requests creates an empty table with restrictive composite membership FK, membership index and tenant/status/created index for abandoned-request review. No history edits. Rollback requires disabling AI, exporting metadata, then separately approved removal of the new table.

Admission and ai.request.started audit commit atomically before the provider is called. This admission point is the future quota/budget hook (reserve by tenant/user before provider). No distributed quota/rate-limit promise is made. The call occurs once outside DB transactions, with timeout/AbortSignal, no automatic retry that could double charge. Terminal status and success/failure audit commit atomically; provider internals never enter errors/audit/logs. Response is released only after successful completion and authorization recheck. HTTP correlation uses existing AsyncLocalStorage. Internal calls without HTTP context receive their own request ID; SYSTEM audits link by resource ID.

Provider failure/timeout records FAILED with safe category. Persistence failure returns AI_INTERNAL_ERROR; failure recording is attempted but if persistence/audit remains unavailable the record can remain STARTED (unknown outcome), never falsely SUCCEEDED. A terminal SUCCEEDED record is not overwritten after an uncertain commit response. Crash-left STARTED records require operator reconciliation; no blind replay, worker or scheduler. A future external adapter might finish billable work despite cancellation; timeouts do not prove provider cancellation. Actual mock computation is local and finite.

Structured application logging and durable metadata expose only request/tenant/user IDs, selected provider/model, status, latency and safe categories. Prompts and outputs are neither persisted nor logged. Existing denied-permission audits are reused; validation failures use the existing safe error/log infrastructure without copying input. HTTP statuses 401/403 and DTO errors stay compatible; provider unavailable/timeout 503 AI_PROVIDER_UNAVAILABLE, limit 429 AI_LIMIT_EXCEEDED, malformed/failing provider 502 AI_PROVIDER_ERROR, persistence 500 AI_INTERNAL_ERROR. Post-call permission revocation returns 403 FORBIDDEN and discards output.

Out of scope: real external providers/credentials, streaming, conversations, RAG, embeddings, vectors, agents, tool execution, autonomous mutations, OCR/document intelligence, fine-tuning, prompt marketplaces, distributed quotas, cost pricing and frontend. No frontend integration is required for this task.
