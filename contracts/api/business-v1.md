DXOS-DOMAIN-003 availability update: Departments is implemented with served OpenAPI; Employee and Task are implemented by the subsequent domain tasks. Department's contract documents parser-level 400/413 failures that precede authentication. The authorization ordering below describes requests that successfully pass transport parsing.

All operations use Bearer IAM authentication, active User/session, active Organization and membership, and exact existing-RBAC catalog grants to be added explicitly in implementation. No admin/owner wildcard or automatic new grants. Tenant comes exclusively from validated route context; never JWT claims, client body, referenced resource or frontend selection alone. All database reads/writes, joins, uniqueness checks and cursors are tenant constrained.

Authorization order: IAM → tenant authorization → operation/field permissions → strict input validation → tenant-scoped resource/reference lookup → lifecycle checks → transactional mutation reauthorization. Missing/invalid/expired/revoked session or inactive account returns 401. Invalid, unknown or inaccessible organization and missing required grant return 403 FORBIDDEN without existence details, consistent with organization APIs. Valid authorized tenant plus missing or foreign resource/reference returns identical 404 NOT_FOUND. Invalid DTO fields, UUIDs or query values return 400 VALIDATION_FAILED after authorization; malformed transport input outside DTO validation returns 400 BAD_REQUEST. Business state/uniqueness conflicts return 409 CONFLICT only after tenant-scoped lookup. Do not expose foreign names, state or IDs in errors. Use the [existing error envelope](error-envelope.md) and safe requestId. Unexpected database/audit failures use safe 500 responses and rollback, not success or a fabricated validation failure.

Bodies are strict JSON objects. Reject unknown keys, roles/permissions, tenant/creator/timestamp injection, empty PATCH, arrays and unsupported nulls. IDs are UUIDs. Partial updates distinguish omitted (unchanged) from explicitly null (clear only nullable fields). Strings have the field-specific lengths/control rules; never render description as executable HTML. No generic nested Prisma input. Maximum JSON body 64 KiB for these future endpoints, enforced before parsing; excessive body 413.

GET collection response `{items:[Resource],nextCursor:string|null}`. Query `limit` integer 1–100 default 25, optional `after` UUID, plus only documented filters. Fixed ascending ID keyset order, `id > after`, tenant and filters applied to every page; cursor is a bound, not a lookup or authorization token. No total count or snapshot guarantee. Clients retain filters across pages/reset cursor on filter changes. UUID filters never cause foreign lookups; missing/foreign/no-match filter yields 200 empty page, malformed UUID yields 400. Enum filters accept one exact value; no array/comma syntax, arbitrary search or sort. Omitted filters include all lifecycle states. Unknown query keys rejected. No expansion/nested credentials. Detail/create/update return the documented resource directly, without an extra success envelope.

Required implementation tests: tenant A/B route/resource/reference/cursor tampering, revoked session/membership, exact permission and mixed PATCH-field matrix, unknown privilege fields, duplicate races, active-state races, lifecycle transitions, pagination, notification/audit rollback, safe projections and contract limits. Design-only changes need no new runtime tests.
# Chấm công theo vị trí — cập nhật 22/10/2026

- JWT, membership ACTIVE và quyền organization theo guard RBAC hiện có; không tự cấp thêm quyền.
- GET `/api/v1/organizations/:organizationId/attendance/location`: `attendance:read`. Trả `{office: {label,latitude,longitude,updatedAt}|null, radiusMeters:100, maxAccuracyMeters:50, maxAgeSeconds:60}`.
- PUT cùng URL: `attendance:manage`, JSON `{label,latitude,longitude}`; không nhận organizationId/radius/quyền trong body. Audit `attendance.location_updated`, không ghi tọa độ vào metadata.
- POST check-in/check-out yêu cầu `{note?, location:{latitude,longitude,accuracyMeters,capturedAt}}`. Quyền tương ứng `attendance:check-in` / `attendance:check-out`. Tọa độ WGS84, độ; sai số mét, 0–50; timestamp ISO mới trong 60 giây, tối đa 5 giây tương lai. Giờ chấm công vẫn do server quyết định.
- Khoảng cách Haversine tới vị trí công ty + sai số GPS phải <=100 m. Backend kiểm trong transaction trước mọi ghi chấm công. Không lưu GPS nhân viên; phản hồi record chấm công giữ nguyên.
- 400: mẫu thiếu/lỗi/cũ (`ATTENDANCE_LOCATION_INVALID` / `ATTENDANCE_LOCATION_EXPIRED`, hoặc validation envelope), quy tắc ca làm hiện có. 401: chưa đăng nhập. 403: sai tenant/membership/quyền hoặc `ATTENDANCE_OUTSIDE_OFFICE`. 409: `ATTENDANCE_LOCATION_NOT_CONFIGURED`, hoặc xung đột chấm công hiện có. Không phân biệt 404 cho tenant ngoại; guard từ chối 403 trước đọc chính sách.
- Đây là thay đổi siết input, client cũ không có GPS sẽ nhận 400; triển khai cùng frontend mới, không fallback bỏ geofence. Xem kế hoạch `docs/architecture/attendance-location-100m.md`. Vị trí trình duyệt có thể bị giả, không là chứng minh hiện diện tuyệt đối.

## Permission review — 22/10/2026

Automation execution discovery requires automation:read; manual scanning requires automation:manage, with JWT and ACTIVE organization membership. Background system scans use a separate trusted service entry point. HR document owner access also requires ACTIVE membership. SENSITIVE filters remain owner-scoped without document:sensitive:read; generic file metadata/content/catalog, search and task attachment references retain the sensitivity boundary. Updating or downgrading another employee's sensitive document also requires sensitive access. Response shapes and schema are unchanged; no extra permissions are granted. See docs/architecture/permission-reference.md for the complete catalog and controller/service intersections.
